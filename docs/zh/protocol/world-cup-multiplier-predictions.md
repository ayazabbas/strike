# 倍数预测协议

Strike 倍数预测是可用于 2026 世界杯等事件系列的固定倍率、精确结果预测产品。本页说明协议行为、经济模型、覆盖、结算、API 与金库职责。

用户教程见[倍数预测](../getting-started/world-cup-multiplier-predictions.md)。线上入口：[strike.fun/world-cup-multiplier-predictions](https://strike.fun/world-cup-multiplier-predictions)。

## 事件模型

每个倍数预测事件都有管理员配置的结果。结果代表受支持事件系列中可客观结算的字段，例如比赛比分、胜方或其他清晰定义的事件结果。每个可选结果都有指定倍率。

用户可以在一次预测中选择一个或多个结果。组合倍率等于所选结果倍率的乘积。只有当每个所选结果都正确结算时，预测才会获胜。

## 池子与经济模型

倍数预测使用两个池子：

- **预测奖池** — 来自已接受的用户预测金额。
- **奖励兜底池** — 来自用户贡献；贡献者可能从预测奖池剩余奖励中获益，同时提供兜底覆盖。

当前产品经济规则：

- 预测奖池剩余部分 100% 分配给奖励兜底池贡献者。
- 平台对剩余预测奖池保留或抽成为 0%。
- 该产品方向下，预测金额、获胜赔付和贡献者奖励费用为 0%。

如果没有预测获胜，或者获胜预测没有用完整个预测奖池，剩余预测奖池会按比例分配给奖励兜底池贡献者。如果获胜赔付超过预测奖池，奖励兜底池可以用于补足已接受预测的差额。

## 覆盖

在请求报价前，前端会估算当前奖励兜底池是否可以支持所选倍率和预测金额。如果覆盖额度看起来不足，界面可能会显示降低后的最大预测金额。

这个预检只是客户端估算。API 报价和金库交易检查才是接受金额和覆盖限制的权威来源。

覆盖检查应考虑：

- 所选结果和组合倍率；
- 请求的预测金额；
- 当前预测奖池和奖励兜底池余额；
- 已接受预测的现有风险敞口；
- 事件状态和提交窗口；
- 金库限制和交易状态。

## 结算与赔付流程

结果数据可用后，事件会按配置结果结算。每个预测按全中或不中评估：

- 如果每个所选结果都正确，该预测可以领取符合规则的赔付。
- 如果任意所选结果错误，该预测不会获得获胜赔付。
- 如果事件被取消或标记为可退款，符合条件的预测收据可以显示退款操作。

结算会确定获胜赔付、预测奖池剩余资金、奖励兜底池使用量、贡献者奖励，以及最终领取或退款可用性。

## Earn 与贡献者风险

奖励兜底池贡献者可能按比例获得预测奖池剩余资金奖励。贡献也存在下行风险，因为当预测奖池不足时，该池子可以用于覆盖已接受的获胜预测赔付。

贡献者会计必须保持贡献余额、提款、奖励、覆盖义务和结算状态一致。应用可以显示估算值，但 API 和金库是贡献、提款、领取、退款和结算状态的权威来源。

## API 职责

API 负责向前端和管理端一致地暴露事件、报价、收据、投资组合与结算数据。

预期 API 行为包括：

- 提供开放中和历史倍数预测事件；
- 返回可选结果和配置倍率；
- 报价组合倍率、接受的预测金额和潜在赔付；
- 执行事件状态、时间窗口和覆盖约束；
- 记录已接受的预测收据；
- 暴露奖励兜底池贡献和提款状态；
- 暴露领取、退款和贡献者奖励可用性；
- 支持管理员结算和事件生命周期操作。

API 响应应明确哪些值是估算值，哪些值是已接受或已结算值。

## 金库职责

金库是 token 转移和已接受链上状态的权威来源。用户操作可能需要先授权 USDT，再提交对应金库交易。

金库职责包括：

- 接受开放事件的预测金额；
- 接受奖励兜底池贡献；
- 在交易时执行覆盖和事件状态检查；
- 在结算、领取、退款、提款或贡献者奖励分配之前保管资金；
- 支付符合条件的获胜预测领取；
- 处理取消或可退款事件的退款；
- 在结算后分配符合条件的贡献者奖励。

前端和 API 检查应减少失败交易，但金库检查仍然是权威检查。

## 收据与投资组合

投资组合收据应显示倍数预测条目、状态、所选结果、预测金额、潜在赔付或退款、交易链接，以及可用时的领取或退款操作。

贡献者视图应显示奖励兜底池贡献状态、估算或已结算奖励、可提款金额，以及与当前事件相关的风险或覆盖状态。
